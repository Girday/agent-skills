## Codex में इंस्टॉल करना

Codex से कहें:

```text
$skill-installer का उपयोग करके https://github.com/Girday/agent-skills/tree/main/skills/gost-7-32-2017-latex इंस्टॉल करो।
```

या रिपॉज़िटरी क्लोन करके स्थानीय प्रति इंस्टॉल करें:

```bash
git clone https://github.com/Girday/agent-skills.git
cd agent-skills
python3 scripts/install.py gost-7-32-2017-latex
```

इंस्टॉलर `$CODEX_HOME/skills` का उपयोग करता है। `CODEX_HOME` सेट न होने पर `~/.codex/skills` इस्तेमाल होता है। यह मौजूदा इंस्टॉलेशन को अधिलेखित नहीं करता। इंस्टॉल की गई प्रति रिपॉज़िटरी से स्वतंत्र है और अपने आप अपडेट नहीं होती। कौशल न दिखे तो Codex दोबारा शुरू करें। खोज और वितरण के विकल्प [आधिकारिक दस्तावेज़](https://learn.chatgpt.com/docs/build-skills) में हैं। यह रिपॉज़िटरी कौशलों के स्रोत देती है; यह प्रकाशित प्लगइन डायरेक्टरी प्रविष्टि नहीं है।

`SKILL.md` का समर्थन करने वाले दूसरे एजेंट भी इन संसाधनों का उपयोग कर सकते हैं। Codex के डेस्कटॉप टूल वैकल्पिक हैं; कमांड लाइन का तरीका भी उपलब्ध है।

## एजेंट के लिए संदर्भ तैयार करना

उसी इंस्टॉलर से नाम या GitHub फ़ोल्डर देकर `build-agent-context` इंस्टॉल करें। फिर कहें:

```text
$build-agent-context का उपयोग करो। इस संग्रह फ़ाइल से संदर्भ तैयार करो ताकि
दूसरा एजेंट परियोजना आगे बढ़ा सके। वर्तमान आवश्यकताएँ, स्रोत, अनसुलझे विरोध
और शुरुआती प्रॉम्प्ट शामिल करो। प्राप्तकर्ता एजेंट फ़ाइलें पढ़ सकता है।
```

कौशल एक संपूर्ण दस्तावेज़ या छोटे प्रवेश दस्तावेज़ के साथ विषयवार फ़ाइलें चुनता है। यह वास्तव में पढ़ी गई सामग्री दर्ज करता है, मूल अंशों के संदर्भ सुरक्षित रखता है और आवश्यकताओं, सत्यापित तथ्यों, धारणाओं व प्रगति को अलग करता है। मौजूदा संदर्भ अपडेट भी किया जा सकता है। कोई अनिवार्य रनटाइम निर्भरता नहीं है; संग्रह फ़ाइलों, स्कैन और अन्य फ़ॉर्मैट के लिए उपयुक्त साधन चाहिए।

पद्धति का आधार (12 चुने हुए प्रकाशन), परिणामों के उदाहरण, गुणवत्ता मानदंड, व्यवहार मूल्यांकन और सत्यापन की सीमाएँ:

## GOST कौशल का उपयोग

```text
$gost-7-32-2017-latex का उपयोग करो। संलग्न सामग्री से रिपोर्ट तैयार करो,
PDF बनाओ और फ़ॉर्मैट जाँचो। संस्थान की आवश्यकताएँ अलग से संलग्न हैं।
```

रिपॉज़िटरी के मूल फ़ोल्डर से चलाएँ:

```bash
python3 skills/gost-7-32-2017-latex/scripts/init_project.py ./my-report
python3 skills/gost-7-32-2017-latex/scripts/build.py ./my-report
python3 skills/gost-7-32-2017-latex/scripts/audit.py ./my-report
```

`init_project.py` के बाद `my-report/metadata.tex` भरें और बिल्ड करने से पहले उदाहरण सामग्री बदलें। टेम्पलेट में कुछ फ़ील्ड जानबूझकर खाली हैं; उन्हें भरने तक ऑडिट विफल होना चाहिए। PDF के ज्यामितीय माप जाँचने के लिए `pdfplumber` इंस्टॉल करें; इसके बिना संबंधित जाँच `NOT_CHECKED` रहती हैं।

आठ पृष्ठों का उदाहरण, आवश्यकताओं का मानचित्र और सत्यापित व्यवहार व सीमाएँ:

- [example.pdf](../examples/gost-7-32-2017/example.pdf)
- [requirements.md](../skills/gost-7-32-2017-latex/references/requirements.md)
- [validation.md](../skills/gost-7-32-2017-latex/references/validation.md)

GOST 7.32-2017 शोध रिपोर्टों के लिए है। पाठ्यक्रम के काम में इसे अपनाते समय संस्थान के नियमों के अनुसार बदलाव जरूरी हैं। कौशल आवश्यकताओं, सुझावों, अनुमत विकल्पों और टेम्पलेट के चुनावों में अंतर करता है। स्वचालित जाँच समीक्षा में मदद करती हैं; वे रिपोर्ट को प्रमाणित नहीं करतीं और हस्ताक्षर, पंजीकरण या संस्थागत स्वीकृति की पुष्टि नहीं करतीं। A3 और बहुखंड रिपोर्ट की प्रक्रियाएँ दर्ज हैं, लेकिन शुरुआती सत्यापन में अलग से नहीं परखी गईं।

## विकास

वर्चुअल एनवायरनमेंट बनाएँ और अपने shell की कमांड से सक्रिय करें; फिर निर्भरताएँ इंस्टॉल करके जाँच चलाएँ:

```bash
python3 -m venv .venv
python -m pip install -r requirements-dev.txt
python scripts/validate.py
python -m unittest discover -s tests -v
ruff check .
ruff format --check .
```

XeLaTeX उपलब्ध होने पर LaTeX इंटीग्रेशन टेस्ट चलता है, अन्यथा छोड़ दिया जाता है। GitHub Actions स्रोत और Python टेस्ट जाँचता है; यह बनी रिपोर्टों को रेंडर या प्रमाणित नहीं करता।
