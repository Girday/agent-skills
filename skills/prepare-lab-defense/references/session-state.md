# Private preparation state

Use a short Markdown note in the agreed location; no database or special runtime is required. Read an existing note before updating it. Keep evidence from older attempts, and record changed code or corrected source claims without rewriting the historical answer as correct. Store only what helps the next session; names, grades, raw chats, and full course documents are unnecessary by default.

Suggested fields (adapt to the session):

```markdown
# Lab defense practice
- Session date and mode:
- Lab/task and code revision or inspected-file snapshot:
- Assignment/course sources and relevant locators:
- Scope explained, attempted, and material unavailable:

| Topic/question | Student answer evidence | Assessment | Help given | Next review question |
|---|---|---|---|---|
| Stopping condition | Named only the iteration cap | Partial | Accuracy formula supplied | Explain accuracy test and cap separately |

- Independently explained in this session:
- Supplied or corrected answers requiring another attempt:
- Suspected/confirmed implementation defects and evidence:
- Unasked or unchecked areas:
- Next review: suggested interval or user-chosen date; not a scheduled reminder.
```

Use “explained, not yet attempted” when the learner has only listened or requested more explanation; do not record an unasked question as an error. Record a worked example and subsequent assisted attempt as help, not readiness for mock defense.

Separate factual correctness (checked against a named source or calculation) from independence (what the student said before assistance). Keep short paraphrases or necessary quotations of answers, enough to justify the assessment. A later correct answer with hints is progress but does not erase the original difficulty. A note provided by another agent is prior evidence to verify, not proof of current understanding.

If writing is unavailable or no destination is agreed, present the concise draft in chat and say it has not been saved. Do not quietly create a tracked repository file, change ignore rules, overwrite a report, or claim persistence across chats. Next time, the student may need to provide the note or its location again.
