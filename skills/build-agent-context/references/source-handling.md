# Разбор источников

Читай только разделы для имеющихся материалов. Выбирай доступные инструменты, не делая конкретный сервис обязательной зависимостью.

## Архив

1. Просмотри список записей, типы, количество, размеры и вложенные архивы до распаковки. ZIP можно осмотреть через `python -m zipfile -l INPUT.zip`, TAR — через `tar -tvf INPUT.tar`. Это только инвентаризация.
2. Проверь, что извлекаемые имена остаются внутри отдельной папки назначения. Исключи абсолютные пути, выход через `..`, симлинки/жёсткие ссылки наружу и специальные файлы; используй распаковщик, который обеспечивает эти ограничения. При отсутствии такой гарантии читай выбранные обычные записи без извлечения или используй изолированную среду.
3. Ограничь объём извлечения, число записей и глубину вложений по доступному диску и задаче. Метаданные размеров не заменяют контроль фактически извлечённого объёма. Не разворачивай вложенные архивы рекурсивно без оценки.
4. Сохрани соответствие `архив → путь записи → извлечённый файл`. Распаковывай в новую папку, не поверх рабочего проекта. Парольный, повреждённый или неподдерживаемый архив отметь как недоступный; обрабатывай остальное.

Не запускай скрипты, установщики и макросы из архива для его «изучения». Полезные команды из материалов можно описать с происхождением и статусом проверки. Запуск требует отдельного основания в задаче.

## Документы, таблицы и изображения

Используй доступный парсер документов или OCR; если в среде есть профильный навык чтения, соблюдай его рабочий процесс. Для небольшого набора достаточно доступных средств извлечения и визуальной проверки. Не устанавливай тяжёлый парсер без необходимости.

Для каждого документа различай обнаружение, извлечение текста, чтение и визуальную проверку. Укажи обработанные страницы/разделы и оставшийся объём. Для сканов не превращай уверенное оформление OCR в доказательство точности.

- Сверяй формулы, индексы, знаки, числа и единицы с изображением оригинала, когда от них зависит работа. Сомнительные места помечай и сохраняй локатор для проверки.
- У таблицы сохраняй заголовки, единицы, период, строки/колонки и примечания. Для книги таблиц указывай лист и диапазон; формула и отображённый результат — разные сведения.
- Для графика сохраняй подписи осей, легенду, масштаб и источник данных. Если доступно только изображение, не изобретай точные значения.
- Для презентации указывай номер слайда; важные схемы и подписи проверяй визуально.

Для больших документов начни с содержания, требований и целевых разделов. Затем расширяй охват по зависимостям: определение символа, условие теоремы, приложение с данными. Явно укажи, что остальная часть пока не прочитана.

## Переписка и ссылки

Сохраняй автора, дату с часовым поясом при наличии, идентификатор сообщения и тему. Отделяй предложение, вопрос, согласование и окончательное решение. Цитата чужого письма не равна новому указанию его переславшего.

Для веб-источника запиши название, автора/организацию, канонический URL, дату публикации/версии, если найдена, и дату обращения. Поисковый сниппет не подтверждает весь материал. При неработающей ссылке отметь отсутствие доступа. Если есть только предоставленный фрагмент, атрибутируй именно его.

Не отправляй приватные материалы во внешние сервисы без разрешения. Сохраняй в производном контексте только необходимые персональные данные. Вместо секрета укажи безопасную ссылку на место его получения; не копируй значение в индекс, примеры и стартовый запрос.

## Репозиторий

Прочитай действующие инструкции, состояние Git и файлы запуска/проверки. Отдели архитектуру и соглашения от текущих изменений и локальной среды.

Зафиксируй ревизию для фактов о коде и отметь существенные незакоммиченные изменения. Ссылку на функцию сопровождай путём и именем символа; номера строк без ревизии быстро устаревают. Команды перечисляй с рабочим каталогом, требованиями и статусом: найдена в документации, запущена, завершилась успешно или не проверялась. Локальная проверка не доказывает результат CI или развёртывания.

Для генерации контекста обычно достаточно чтения. Если запуск тестов нужен, используй доверенный проект и уже разрешённые операции; вложенный неизвестный код не запускай автоматически. Не меняй `.gitignore`, зависимости и структуру проекта ради размещения заметок без основания в запросе.

## Большой или обновляемый набор

Сначала составь полный доступный каталог, затем прочитай приоритетные источники. Объединяй точные дубликаты по содержимому, сохраняя исходные пути; похожие названия ещё не означают дубликат.

Для изменяемого корпуса полезны размер и хеш файла, если их сбор оправдан. Дата изменения помогает находить изменения, но не устанавливает истинность документа. При обновлении:

1. Сравни состав и версии с предыдущим каталогом.
2. Найди справки и решения, опирающиеся на изменившийся источник.
3. Перепроверь их, обнови локаторы и состояние; сохрани важные причины прошлых решений.
4. Удали опровергнутое из актуальной точки входа, оставив помеченную историю там, где она нужна.

Не пересказывай старое резюме снова и снова без обращения к исходным доказательствам. Если оригинал больше недоступен, отметь, какие выводы теперь нельзя перепроверить.
